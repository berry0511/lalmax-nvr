# GB28181 真机复测

使用修复分支构建的 NVR 前后端，在授权测试窗口使用已配置的 KtyQGC / EasyGBD 测试设备：

- DeviceID：`34020000001320482713`
- ChannelID：`34020000001310482714`

1. 验证注册、通道目录及在线状态。保留现有 Camera、设备和录像。
2. 点击开始推流。核对 INVITE → 200 → ACK、Camera DB/runtime 已就绪，以及 `is_playing=true`。对照此次 Call-ID 和接收器 SessionID。
3. 等待实际媒体，核对独立媒体状态与 WebRTC 首帧。切换录像开关后，点播会话状态不应被录像状态覆盖。
4. 点击停止推流。核对 BYE → 200、仅目标 RTP 接收器关闭、通道不再点播、设备保持在线。多个通道时检查其余通道无中断。
5. 再次 Play，核对新的 Call-ID/SessionID、媒体和浏览器预览。使用「重启推流」重复，检查网络面板只出现 GB28181 Stop/Play 控制请求，没有 Camera Start/Stop。
6. 可在专用测试窗口验证「重启录像」仅使用 Camera API；录像状态变化不得导致 SIP 重邀约。
7. 通道断开或后端重启后再次执行，不应清空数据、删除设备或要求重新注册；核对同一 Camera 记录、录像计划及已有录像仍在。
8. 记录部署 SHA、测试时间、SIP/媒体结果及通过/失败。若无设备或未测试，不以模拟用例代替，标为 `NOT_TESTED`。

日志：systemd 用对应 unit 的 journal，手动启动看部署脚本的标准输出重定向。记录结构化日志，勿粘贴认证信息或完整 SIP 报文。
