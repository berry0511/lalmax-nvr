# 事件中心

事件中心把设备健康、录像恢复、AI 检测和 MQTT 触发记录放在同一时间线中。支持按摄像头、来源和处理状态筛选，分页查看并确认待处理事件。页面通过服务端事件订阅接收更新后刷新列表；也可手动刷新。

## 事件来源

| 来源 | 内容 |
|------|------|
| `health` | 摄像头连接丢失/恢复、码流异常、画面冻结/恢复等健康事件 |
| `recorder` | 录像器断线后恢复，记录中断时长、重试次数和录像关联信息 |
| `ai` | 浏览器或 Webhook 检测器上报的目标检测；相同摄像头和类别组合在 30 秒内会抑制重复事件 |
| `mqtt` | MQTT 触发器执行的摄像头动作，例如开始/停止录像 |

事件状态为 `open`（待处理）或 `acknowledged`（已确认）。确认事件会记录确认时间；事件详情保留来源、类型、级别、消息、时间以及可用的录像 ID、快照和元数据。具备操作权限的用户可确认或删除事件。

## 告警规则

在事件中心的规则区域，可为摄像头和事件来源添加规则，并选择以下动作：

- **录像**：触发关联摄像头的事件录像。
- **Webhook**：向配置的接收地址发送事件通知。
- **转到预置位**：请求摄像头移动到配置的 PTZ 预置位。

规则的来源、摄像头和动作目标应与设备能力及对应服务配置匹配。MQTT 触发录像的主题和动作格式见 [MQTT 集成](mqtt-integration.md)。

## 排查

若事件未显示，先确认产生事件的摄像头 ID 与 NVR 中的设备一致，再清除来源/状态筛选。浏览器端 AI 需要启用 AI、加载模型并使用 WebCodecs 播放；只出现实时画面并不表示检测到目标。事件 API 与实时订阅路径见运行中 NVR 的 `/docs/`。
